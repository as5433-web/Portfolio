Personal Portfolio Website Report

Andrew Soleiman · November 6, 2026

Purpose and features

I built a personal portfolio to present my education, electronics projects, and technical skills to potential employers. The website introduces me as an Electronics & Computer Engineering Technology student at New Jersey Institute of Technology, with personal interests in low-voltage circuits and analog audio systems.

The site has five separate pages: Home, About, Projects, Skills, and Contact. About covers my education, selected County College of Morris coursework, work experience, and future study goals. Projects presents a self-playing guitar amplifier, an electronic calculator, and an Arduino rover, with team contributions credited. The amplifier and calculator each include a finished-build photo, a schematic, and a PDF lab report. Skills organizes demonstrated capabilities and tool experience. Contact links to LinkedIn without publishing my private contact details.

I used plain HTML, external CSS, and JavaScript, with no framework or backend. The shared navy, blue, and pink design supports phone and laptop layouts. Semantic headings, descriptive image alternatives, a skip link, visible keyboard focus, and active-page navigation support accessibility.

JavaScript and deployment

The mobile menu button opens and closes navigation and updates its expanded state. Escape closes the menu and returns focus to its button. The theme toggle changes a data attribute on the document, allowing CSS variables to switch between light and dark colors. JavaScript remembers the theme with localStorage and catches storage errors so controls still work when storage is unavailable. Home also has CSS waveform and speaker animations that stop when reduced motion is requested.

I published the site through GitHub Pages from the main branch and repository root. Relative links and asset paths support both the capitalized /Portfolio/ deployment path and direct local opening. Each project image is below 500 KB, and larger views open when selected.

Challenges and an actual Codex correction

Codex's first waveform animation changed the bars together, producing a wobbling effect rather than the sound pulse I requested. I clarified the motion and reviewed revisions. The corrected animation sends one pulse from left to right in 1.6 seconds, followed by 0.4 seconds of rest. The speaker cones follow my specified rhythm while the cabinet stays still. This showed why reviewing generated behavior against a precise requirement matters.

Testing and remaining limitation

I completed the 44 planned manual test cases, including phone/laptop layouts, links, images, PDFs, keyboard navigation, mobile-menu behavior, theme persistence, reduced motion, privacy, and local opening with unavailable storage. All were recorded as passed based on my testing and supplied evidence. A separate automated live HTTP/source audit recorded 67 passes. The detailed procedures, results, and evidence references are in TESTING.md.

Desktop Lighthouse results were 100 in Performance, Accessibility, Best Practices, and SEO on all five pages. Skills' mobile retest also scored 100 in every category. Projects initially scored 89 for mobile Performance; a later run scored 99, with the other three categories at 100. Its layout-shift score changed from 0.203 to 0 without an intervening code change.

A local diagnostic probe reproduced an approximately 199-pixel content jump when JavaScript collapsed the initially visible mobile navigation. This identified header initialization as the leading explanation for the intermittent shift. I have not claimed a permanent fix: the later passing behavior documents that run, while the investigation remains recorded. Smaller image previews are another possible future improvement.
